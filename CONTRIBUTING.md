# Руководство по внесению изменений в проект Backend4sem

##  Git Flow

Мы используем Git Flow для управления версиями:

- `main` — стабильная версия (только релизы)
- `develop` — основная ветка разработки
- `feature/*` — ветки для новых функций

Все коммиты должны следовать формату Conventional Commits:
Типы коммитов:
feat: — новая функция (например, feat: add product model)
fix: — исправление ошибки (например, fix: correct pagination bug)
docs: — изменения в документации (например, docs: update README)
style: — форматирование, отступы (не влияющие на код)
refactor: — рефакторинг без изменения функциональности
test: — добавление тестов
chore: — изменение конфигурации, обновление зависимостей
